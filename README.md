# 国际中文联合培养履约协同

面向广西高校与东盟院校联合培养班的履约协同服务：把招生名额、课程交付、师资派出、
资源提供、成果归属等事项统一为带生效期的协议版本，各方在权限内提出条款、逐项会签，
后续变更只能通过修订案推进，履约过程全程留痕、可核验。

## 核心规则

- **权限内提案**：合作方只能提出自己权限内的条款类别；协调方（学院）可汇总各方已确认的变更提出修订案。
- **逐项会签**：会签只对特定内容哈希负责；条款被修订或会签过期后，旧会签自动失效，不得污染较新的决定。
- **版本与修订案**：首个版本由草案激活产生，此后变更只能走修订案；修订案必须基于当前生效版本，并发修订中落后的一方在生效时被拒绝，不能覆盖较新的决定。
- **承诺挂接条款**：版本生效时按条款模板登记履约承诺；已执行（有履约记录或证据）的承诺不被修订覆盖，只有尚未启动的承诺才会被替代。
- **履约状态与证据链**：待履行、部分履行、已履行、迟交履行、替代履行、逾期未履、争议中均有明确状态；每条承诺挂一条哈希衔接的证据链，篡改可被发现。
- **业务时钟**：提醒与逾期升级由注入的业务时钟计算（`ManualClock` 可用于演练与测试）。
- **重启恢复**：所有决策以哈希链事件落盘（JSONL），进程重启后待确认事项仍在，可继续会签。
- **历史查询**：管理员按培养批次与历史时点查询当时适用的协议、各方未履约项、修订影响与可核验的决策记录。

## 模块

| 模块 | 职责 |
| --- | --- |
| `contracts.py` | 基础契约（版本化实体、关联记录） |
| `domain.py` | 条款、版本、修订案、履约承诺、证据链等领域模型 |
| `clock.py` | 业务时钟（系统时钟 / 可手动推进的时钟） |
| `store.py` | 追加式事件存储，哈希链校验 |
| `service.py` | 协同服务：会签、激活、修订、履约登记、提醒升级 |
| `queries.py` | 管理员查询端点：历史协议、未履约项、修订影响、决策记录 |

运行测试：

    python3 -m unittest discover -s tests -v

编译检查：

    python3 -m compileall -q src tests run_cli.py

命令行冒烟（演示完整业务流程，事件写入 `data/demo-events.jsonl`）：

    python3 run_cli.py
